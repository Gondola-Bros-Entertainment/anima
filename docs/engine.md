# Engine and animated GLB preview

Anima provides a C++20 core, headless asset/animation runtime and an SDL3/Vulkan
viewer. External applications consume public targets and compose independent
scene instances. See [consumer/API instructions](consuming-anima.md) and the
optional [RmlUi integration](ui-integration.md).

## Build and run

Requires CMake 3.25+, a C++20 compiler, and (desktop only) SDL3 3.2+ plus a Vulkan
SDK with `glslc`. The tested SDK is 1.4.341.1. Use the same CPU architecture for
all dependencies. Tests and GPU verification tools require Python 3.10+.
macOS uses MoltenVK; Windows/Linux need a Vulkan GPU driver.
No GPU, SDL, Vulkan, image library or asset parser is needed for the `core` preset.
The desktop configure step checks for headers declaring
`VK_EXT_surface_maintenance1` and `VK_EXT_swapchain_maintenance1`. These declarations
are required to compile; device support is queried at runtime and is optional.
The Vulkan 1.1 runtime baseline is separate from the build-time header requirement.

Run from the repository root:

```sh
cmake --preset core
cmake --build --preset core
ctest --preset core
./build/core/anima_headless

cmake --preset headless
cmake --build --preset headless
ctest --preset headless
./build/headless/anima_inspect /path/to/character.glb

cmake --preset desktop
cmake --build --preset desktop
ctest --preset desktop
./build/desktop/anima --validation
./build/desktop/anima --asset /path/to/character.glb --validation
./build/desktop/anima --manifest /path/to/character.asset.json --validation
```

For Visual Studio's multi-configuration generator, executables are in `Debug/`
under the build directory, e.g. `build/desktop/Debug/anima.exe`. Build/test presets
already select Debug. An installed SDL package can be selected with
`-DCMAKE_PREFIX_PATH="path/to/SDL/install"`; source building is available on all
three targets through `cmake --preset desktop -DANIMA_FETCH_SDL=ON`. That optional
fetch uses a pinned commit. Windows copies a shared
SDL DLL beside `anima.exe`. Run in the SDK's configured environment so the Vulkan
loader, driver and validation layer can be discovered. Linux also needs a working
X11 or Wayland session and the corresponding SDL build prerequisites.

On macOS, Homebrew commonly installs SDL3 under `/opt/homebrew` on Apple Silicon.
If an SDK is not found, set `VULKAN_SDK` to its platform SDK
directory and/or supply `CMAKE_PREFIX_PATH`. With multiple ICDs installed, select
MoltenVK explicitly for reproducible GPU verification:

```sh
VK_DRIVER_FILES=/usr/local/share/vulkan/icd.d/MoltenVK_icd.json \
  python3 tools/engine/gpu_smoke.py build/desktop/anima_check \
  --asset /path/to/character.glb --output build/verification
```

On Windows use PowerShell `$env:VK_DRIVER_FILES` if driver selection is necessary,
and pass the `.exe` path to the Python runner. Ordinary `ctest` never opens a
window. Use the
[local qualification workflow](local-qualification.md) for Mac, Windows and Linux
checks alongside the repository's CI checks.
Hardware checks remain separate. Their runner source is under `tests/desktop/`;
application setup, options and the shared viewer loop are under `apps/desktop/`. Local reports and captures stay under `build/`.

CTest also builds standalone core/asset consumers in a separate source/build
directory; the desktop preset adds a desktop consumer. Those ordinary tests do not
open a window. `ANIMA_BUILD_TOOLS` and `ANIMA_BUILD_TESTS` select tools/tests
independently of the asset and desktop libraries; see the consumer guide for defaults.

Build only the triangle desktop app with `-DANIMA_BUILD_ASSETS=OFF`. A GPU is
needed at runtime, not at compile time. Shader SPIR-V is generated by glslc and
embedded into the executable, so launching from another directory works.

## Viewer controls and scope

- Drag with the left mouse button or use arrow keys to orbit.
- Mouse wheel zooms; F frames the asset again; Escape or close exits.
- With `--manifest`: 1/2/3 select available clips, Space pauses/resumes,
  R restarts and B shows the bind pose. The title shows the active clip and time.
  A manifest with no clips opens in bind pose; playback controls leave it static.
- `--clip NAME --time SECONDS --paused` selects an exact held pose; seeking is
  silent. These options require a manifest.
- `--frames N` exits after N successful presentations, with a 20-second deadline.
- Scripted checks use `anima_check`, built with `ANIMA_BUILD_TESTS=ON`. Its
  `--smoke` mode validates resize/minimize/restore; `--preview-smoke DIR` checks
  playback; `--fail-after STAGE` exercises typed initialization failures.
  The ordinary `anima` viewer does not accept these scenario options.
- `--timeout N` changes the frame-mode deadline. `--capture file.ppm` saves the first
  rendered frame through GPU readback. PPM is RGB8; sRGB swapchains are preferred.

The app borrows no input from other programs. Automated runs do not request window
activation. They create only their own windows and do not move the mouse.

The importer loads every triangle primitive of every mesh node in the selected
scene (default scene, otherwise first scene, otherwise root nodes). It respects
nested TRS/matrices and mesh instances, indexed/non-indexed geometry, byte strides,
normalized attributes, material assignments, and inverse-transpose normals.
`load_asset` copies hierarchy, rest transforms, skins, source vertices, decoded
textures and animation channels into immutable shared assets before releasing the
glTF parser. `sample_pose` creates independent local/world transforms; `pose_mesh_snapshot`
computes CPU diagnostic geometry with up to four normalized weights. The viewer
compiles `Mesh` resources and updates GPU skinning palettes through `Scene`.
Skinned mesh transforms follow glTF's convention; they are not applied twice.

The inspector reports **bind pose** when joint-world × inverse-bind matrices meet
the 0.00002 identity tolerance; otherwise it reports **default pose**.
`--asset` provides static inspection. `--manifest` enables the generic `AssetPreview`
and the model's declared animation clips. Keys 1/2/3 select available clips;
Space pauses, R restarts and B restores the bind pose. Equipment composition
belongs to the game. Clip-free manifests preview the bind pose. Independent motion
contracts are consumed by the application's adapter, not the generic viewer.
The bind label does not qualify rig or animation quality.

Materials use opaque or alpha-mask, double-sided metallic/roughness lighting. Embedded PNG/JPEG
base-color images are uploaded as sRGB textures and sampled per pixel. RGB is decoded
before filtering and multiplied by linear base-color factors and vertex colors.
glTF min/mag/mip filters and repeat/clamp/mirror wraps are preserved; missing filters
use linear/trilinear. CPU-generated mipmaps average in linear light, including odd
edge texels. Untextured materials use a white texture. An sRGB swapchain encodes the
lit result; a shader fallback encodes for UNORM swapchains. The glTF scalar metallic
and roughness factors drive GGX specular reflection and diffuse suppression.
Normal, metallic-roughness, occlusion and emissive maps and KHR_materials_unlit are
supported. See [material lighting](../include/anima/desktop/vulkan_renderer.hpp) for texture/UV conventions,
the configurable environment, sky, directional shadows, limitations and verification.

LINEAR channels interpolate translation/scale linearly and normalized rotations
with shortest-path quaternion SLERP. STEP holds the preceding key. Samplers clamp
outside their key range and start each pose from the asset's rest transforms.
CUBICSPLINE, morph channels, duplicate target channels, non-increasing key times and
animation on matrix nodes are rejected explicitly. These conventions follow the
[glTF 2.0 specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html).

Manifests supply clip loop policies. Events fire on forward interval crossings,
including multiple loop crossings; pause and seek emit none. Game code owns combat
meaning, equipment choice and attachment composition. Compatible equipment maps
joints by name, ancestry, inverse binds and rest-world transforms. Socket nodes
must descend from a skin joint. A declared bind signature alone does not prove
compatibility; numerical binding checks still apply.

Unsupported required extensions, sparse accessors, external buffers/images,
compressed meshes/textures, morph targets, non-triangle topology, GPU instancing,
alpha BLEND and more than four skin influences produce explicit errors.
Optional extensions not otherwise rejected are reported as unsupported. Input size,
image size, vertex count and hierarchy depth have bounded import limits. Manifest
JSON is bounded to 1 MiB/depth 32 and model paths must be filenames beside it. This is
an importer for local authored assets, not a hardened untrusted-file service.

## Lifetimes, timing and validation

`anima::core` has no window/renderer dependencies. The fixed-step accumulator uses
integer nanoseconds, caps catch-up, reports dropped time and preserves a fractional
remainder. The desktop app pauses simulation while drawable output is unavailable.
Networking remains outside Anima; applications select and integrate their own
transport.

The desktop renderer owns Vulkan resources and borrows the SDL window. Partial
initialization is cleaned through an already-constructed implementation object.
The renderer shuts down before the window, and the window before SDL. Validation
counts include cleanup and are printed even after an injected construction failure.
`--validation` fails explicitly if the layer is absent; successful validation-mode
runs require zero warnings and errors.

One graphics frame is in flight. Pose palettes are written into the mapped buffer
only after the graphics fence; immutable mesh resources are shared by instances.
Texture uploads use staging memory, explicit barriers and fenced completion.
Scene replacement owns candidate buffers, textures and descriptors separately,
using a dedicated upload command pool/fence. It validates before acquisition and
installs only after successful upload; recoverable failures leave the old GPU scene
usable. Empty consumer scenes clear the background; the viewer explicitly opts
into its diagnostic triangle unless `--empty` is selected. See the
[replacement API contract](consuming-anima.md#renderer-scene-replacement).
The acquire semaphore and command buffer are
protected by the graphics fence. Presentation semaphores belong to **swapchain
images**, following [Khronos guidance](https://docs.vulkan.org/guide/latest/swapchain_semaphore_reuse.html).
Where advertised, `VK_EXT_swapchain_maintenance1` is queried/enabled and presentation
fences are waited before retirement. MoltenVK exercised this path. The
`--no-present-fences` option exercises the Vulkan 1.1 wait-idle fallback. As the
Khronos guide explains, unextended Vulkan has no complete presentation-retirement
fence guarantee; that fallback is a practical compatibility path, not equivalent
to explicit present fences.

Swapchains use SDL's [pixel dimensions](https://wiki.libsdl.org/SDL3/SDL_GetWindowSizeInPixels),
FIFO presentation, queried formats/extents/image counts/alpha modes, and a queried
depth format. Separate graphics/present queue families use concurrent sharing.
Portability enumeration and the advertised portability subset are enabled for
MoltenVK. No acquisition or rendering is attempted for hidden/minimized/zero-pixel
windows. Out-of-date acquisition leaves the frame fence signaled; suboptimal or
out-of-date presentation requests recreation. Surface loss/device loss are fatal
with diagnostics; automatic recovery is not implemented. Recreation waits for idle
and rebuilds resources, so it can stall briefly. This favors a small, inspectable
foundation over throughput.

The Python GPU harness enables synchronization validation with
`VK_LAYER_VALIDATE_SYNC=1`, gives each subprocess a 35-second watchdog, validates
capture content and lifecycle counters, and checks five initialization stages plus
mesh-upload cleanup. The CLI has finite acquisition/frame waits and its own loop deadline. Teardown
waits for presentation completion before destroying resources; driver hangs there
or inside other Vulkan/OS calls require the external watchdog.

## Exported fixture and reproducibility

Use an exported GLB and matching manifest from your application. The paths below
are placeholders; substitute absolute paths to your own files. The engine's
synthetic tests require no production assets or Blender. Exported-model checks
are optional and exercise the importing application's content against the runtime.

Enable additional exported-model regressions with:

```sh
cmake --preset desktop \
  -DANIMA_TEST_GLB="/path/to/character.glb" \
  -DANIMA_TEST_MANIFEST="/path/to/character.asset.json"
cmake --build --preset desktop
ctest --preset desktop
```

Use native absolute fixture paths on Windows as well.
The same fixture options work with `headless`. Synthetic importer and animation
tests run without generated assets or Blender. Pinned
vendored library revisions/licenses are in [third_party/README.md](../third_party/README.md).

Run the additional GPU checks in the same configured Vulkan environment:

```sh
python3 tools/engine/gpu_preview_smoke.py build/desktop/anima_check
python3 tools/engine/gpu_material_smoke.py build/desktop/anima
python3 tools/engine/gpu_pbr_smoke.py build/desktop/anima
```

The preview smoke generates a skinned fixture with Idle and Walk clips. An optional
manifest argument exercises an external asset with those embedded clips.
It does not load application-owned independent motion contracts. Use `--manifest`
with `--frames 1 --capture PATH` for a static model check.

The animated run presents 360 frames at a scripted 1/60-second pose step, exercises
resize/minimize/restore, and writes 28 readbacks. It checks changing Idle/Walk poses, exact pause/restart captures and stable bind restoration.
Texture and in-flight upload failure paths are checked separately. Its process
watchdog is 55 seconds. The material runner generates five embedded-texture quad
fixtures and compares GPU pixels to linear-light expectations.

Consuming projects own asset authoring and export qualification. Each skinned
asset retains its own rest transforms, inverse binds and skin weights. Shared
semantic joint names alone do not make bindings or equipment interchangeable.

Rendering ownership and the boundary between engine facilities and application
effects are documented in the [engine boundary guide](engine-boundaries.md).
